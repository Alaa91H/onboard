# مُثبّت Windows لـOnboard-next

ينتج الأمر الموحد التالي معاينة Windows أصلية لكل من `x64` و`ARM64`:

```powershell
python tools/build.py preview windows --arch x64
```

ينشئ الأمر برنامج التشغيل `onboard-next.exe`، أرشيف ZIP، ومُثبّت Inno Setup بامتداد `.exe`، إضافة إلى ملفات SHA-256 وبيان provenance. لا توجد نصوص PowerShell أو shell وسيطة؛ `tools/build.py` هو نقطة التنفيذ الوحيدة، بينما `packaging/windows/onboard-next-preview.iss` وصفة تثبيت تصريحية يقرأها البرنامج الموحد.

| المخرج | الغرض | الحالة الحالية |
| --- | --- | --- |
| `onboard-next.exe` | تطبيق سطح مكتب مستقل يفتح لوحة مفاتيح Windows Compact فعلية. | معاينة أصلية قابلة للاختبار. |
| `onboard-next-preview-<version>-windows-<arch>.zip` | توزيع محمول بلا تثبيت. | معاينة غير موقعة. |
| `onboard-next-preview-<version>-windows-<arch>-setup.exe` | مُثبّت Windows حديث مع إزالة تثبيت واختصار قائمة ابدأ وخيار تشغيل التطبيق بعد التثبيت. | معاينة غير موقعة. |
| ملفات `.sha256` و`provenance.json` | تحقق سلامة وتحديد منشأ المخرج. | مطلوبة في CI. |

> **حدود الإصدار:** وجود ملف `.exe` ومُثبّت لا يعني أن هذه نسخة مستقرة. التطبيق الحالي يوفّر نافذة لوحة مصغرة، تبديل واجهة العربية والإنجليزية، أزرار إيموجي، وحافظة جلسة، ويحفظ موضع النافذة وإعدادات الواجهة محلياً. يظل اختيار مصدر إدخال Windows الحقيقي عبر TSF قيد التنفيذ، كما يبقى المُثبّت غير موقّع ولا يُنشر خارج معاينات CI قبل اختبار Windows تشغيلي كامل وتوقيع Authenticode واستخدام بيئة الإصدار المحمية.

## تجربة التثبيت والاستخدام

يشغّل المستخدم ملف `setup.exe` مرة واحدة. يثبّت المعالج التطبيق تحت مجلد التطبيقات للمستخدم، وينشئ اختصاراً باسم **Onboard Next** في قائمة ابدأ، ويعرض خيار تشغيله فوراً بعد الإنهاء. عند فتح `onboard-next.exe` لاحقاً، تظهر لوحة مفاتيح صغيرة تبقى فوق النوافذ وتحافظ على حقل الكتابة الخارجي نشطاً؛ وتُرسل الأحرف العربية والإيموجي في Windows كـUTF-16 عبر `SendInput`. يُحفظ موضع وحجم النافذة ولغة الواجهة في التخزين المحلي للتطبيق.

## بدء التطبيق مع تسجيل الدخول

يعرض المُثبّت خياراً غير محدد مسبقاً باسم **Start Onboard Next when I sign in**. عند اختياره، يكتب إدخالاً لكل مستخدم في `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` يشغّل التطبيق بالوسيط `--start-minimized`. لذلك يبدأ التطبيق مخفياً في منطقة الإعلام من دون إزعاج سطح المكتب أو سرقة تركيز حقل الكتابة. يمكن تعطيل الخيار بإعادة تشغيل المُثبّت وإلغاء تحديده، كما يحذف برنامج إزالة التثبيت الإدخال تلقائياً.

## أيقونة منطقة الإعلام والتصغير

بعد تشغيل التطبيق تظهر أيقونة **Onboard Next** في منطقة الإعلام بجانب الساعة. لا ينهي زر الإغلاق التطبيق؛ بل يخفي اللوحة ويُبقي الأيقونة متاحة للاستدعاء. وينطبق السلوك نفسه على زر التصغير القياسي، كما يوفّر زر **إخفاء إلى الأيقونة** داخل اللوحة المسار نفسه.

يؤدي النقر الأيسر على الأيقونة إلى إظهار اللوحة أو إخفائها. أما النقر بالزر الأيمن فيفتح قائمة تتضمن **إظهار اللوحة** و**إخفاء إلى منطقة الإعلام** و**إنهاء Onboard Next**. أمر الإنهاء وحده يغلق العملية نهائياً؛ وبذلك لا تختفي لوحة المفاتيح بسبب الإغلاق العرضي.

عند إظهار اللوحة، يقدم الرأس بطاقة هادئة تتضمن هوية التطبيق وحالة التحديث وأزرار اللغة والحافظة والإيموجي والوصول إلى منطقة الإعلام. يحافظ هذا التنظيم على لوحة مصغرة وغير مشتتة مع إبقاء الإجراءات اليومية في موضع واحد واضح.

## فحص التحديثات

يفحص التطبيق آخر إصدار **مستقر منشور** من صفحة Releases العامة مرة واحدة على الأكثر كل 24 ساعة، أو يدوياً عبر زر **فحص التحديثات**. يقرأ الفحص وسم الإصدار ورابط الصفحة وبيانات ملف التثبيت المطابق للمعمارية إن وجدت، ثم يعرض النتيجة داخل التطبيق. لا ينزّل التطبيق ملفاً ولا يشغّل مُثبّتاً تلقائياً في مرحلة المعاينة.

> **قاعدة الأمان:** لا يُفعّل تنزيل أو تثبيت تلقائي قبل وجود قناة `stable-release` محمية تنشر ملفات EXE موقّعة بـAuthenticode وملف SHA-256 مطابقاً. حتى ذلك الحين لا يتجاوز التطبيق إلى صفحة الإصدار التي يراجعها المستخدم بنفسه.

## التحقق الآلي

يثبّت workflow معاينات Windows إصدار Inno Setup المقفل `6.7.1`، ويبني المخرج على runners من `x64` و`ARM64`، ويتحقق من وجود المـثبّت وعدم فراغه وتطابق SHA-256. تبقى ملفات المعاينة لمدة 14 يوماً في artifacts الخاصة بالتشغيل، ولا تُوقّع ولا تُنشر تلقائياً.

## متطلبات الإصدار المستقر

يتطلب الانتقال من معاينة إلى مُثبّت مستقر ربط شهادة توقيع Windows في secrets محمية، توقيع `onboard-next.exe` وملف setup، التحقق من توقيع Authenticode، اختبار تثبيت وتشغيل وإزالة تثبيت في Windows، ثم رفع artifact عبر workflow إصدار محمي. بعد ذلك فقط يمكن تطوير زر **تنزيل وتثبيت** ليحمّل ملف التثبيت المطابق للمعمارية ويتحقق من SHA-256 وتوقيع Authenticode قبل تشغيله بموافقة صريحة من المستخدم. لا يجوز تجاوز هذه البوابة أو استبدالها بعلامة provenance فقط.
