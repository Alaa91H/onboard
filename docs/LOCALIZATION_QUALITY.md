# جودة اللغات والترجمة في Onboard

يهدف المشروع إلى إبقاء واجهة Onboard قابلة للاستخدام بجميع اللغات المتاحة، مع عدم خلط **سلامة الكتالوج** مع **نسبة اكتمال الترجمة**. تُعد الرسالة غير المترجمة آمنة وظيفياً لأنها تعود إلى النص الأصلي، لكن لا يجوز وسم اللغة بأنها جاهزة للإصدار قبل إزالة الرسائل الناقصة ووسوم `fuzzy` منها.

| مستوى الجودة | المعيار | التعامل في CI |
| --- | --- | --- |
| كتالوج سليم | يمر `msgfmt --check`، ويملك ترويسة `Language` متسقة مع اسمه | إلزامي لجميع ملفات `.po` |
| لغة جزئية | تحتوي رسائل ناقصة أو `fuzzy` لكن تبقى صالحة مع الرجوع إلى النص الأصلي | تُعرض نسبتها في التقرير ولا توقف البناء |
| لغة مكتملة للإصدار | لا تحتوي رسائل ناشطة ناقصة أو `fuzzy`، وتطابق حقول التنسيق النص الأصلي | إلزامي للغة العربية حالياً |

## اتجاه النص

تحدد طبقة `Onboard/I18n.py` اتجاه الواجهة قبل إنشاء نوافذ GTK. وهي تدعم رموز اللغات ذات الاتجاه من اليمين إلى اليسار مثل `ar` و`he`، كما تدعم وسوم الخط الصريحة مثل `az-Arab` و`ku@arabic`. أما أول لغة صريحة غير RTL في سلسلة `LANGUAGE` فتحدد الواجهة باتجاه LTR، وهو سلوك متوافق مع أولوية gettext.

## فحص الجودة

نفّذ الأمر التالي من جذر المستودع للتحقق من كل اللغات وفرض اكتمال العربية:

```bash
python3 tools/build.py validate-translations
```

لإنشاء تقرير قابل للمراجعة بعد التحديثات الكبيرة للترجمة، نفّذ:

```bash
python3 i18n/scripts/check_all_catalogs.py po \
  --require-complete ar \
  --report docs/TRANSLATION_HEALTH.md
```

يمنع CI أي كتالوج غير سليم أو ترويسة لغة مفقودة. كما يمنع نقص الترجمة أو `fuzzy` في العربية، ويحافظ على صحة صيغ الجمع العربية الست. يبقى التقرير `docs/TRANSLATION_HEALTH.md` مرجعاً شفافاً لتحديد اللغات التي تحتاج مساهمات ترجمة بشرية قبل إعلانها مكتملة.

## قواعد المساهمة

ينبغي عدم تعديل `msgid` يدوياً إلا عند تغيير النص المصدر. يجب الحفاظ على علامات التنسيق، مثل `{filename}`، في الترجمة بالترتيب والمعنى المناسبين. ويجب أن تتطابق ترويسة `Language` مع اسم الملف، مع قبول الصيغ القياسية للغات الأساسية مثل `de_DE` في ملف `de.po` ومتغيرات gettext مثل `ca@valencia.po`.
